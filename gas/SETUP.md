# 夜活ガチャ GAS 手動セットアップ

対象は「夜活｜ガチャ抽選用シート」
`https://docs.google.com/spreadsheets/d/1s-N6dr2nZNV5O7RlI66umnhqjtWX8WGN4fh9UAsU0Yw/edit` です。
この作業ではシートへの認証済み接続がなく、実シートの編集やGASデプロイは行っていません。

## 1. ファイルと仕組み

同じ Apps Script プロジェクトに、次のファイルを作成します。

| ローカルファイル | Apps Script上の種類・名前 | 役割 |
|---|---|---|
| `Code.gs` | スクリプト `Code` | 公開関数、ロック、Webアプリ入口 |
| `Config.gs` | スクリプト `Config` | シート名・列名・内部キャンペーンID |
| `SheetService.gs` | スクリプト `SheetService` | シート作成、設定読込、履歴保存 |
| `ValidationService.gs` | スクリプト `ValidationService` | ID、日時、設定値の検証 |
| `LotteryService.gs` | スクリプト `LotteryService` | 開催判定、抽選、重複防止 |
| `Bridge.html` | HTML `Bridge` | GitHub Pagesとのiframe通信 |
| `appsscript.json` | マニフェスト | 日本時間・Webアプリ設定 |

現在のサイトは、GAS Webアプリのiframe内で `google.script.run` を使います。サイトからGASへ直接POSTする構成ではありません。抽選結果はGASが決め、サイトは応答を表示するだけです。

## 2. スプレッドシートへコードを入れる

1. 対象シートを開き、**拡張機能 → Apps Script** を選びます。
2. 最初の `コード.gs` を `Code.gs` の内容で置き換えます。
3. **＋ → スクリプト** で `Config`、`SheetService`、`ValidationService`、`LotteryService` を作り、同名のローカルファイルをそれぞれ貼り付けます。作成順は問いません。
4. **＋ → HTML** で `Bridge` を作り、`Bridge.html` の内容を貼り付けます。
5. **プロジェクトの設定** で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にします。既存のOAuthスコープ等がある場合は消さず、`appsscript.json` の `timeZone`、`runtimeVersion`、`webapp` を反映します。
6. 保存します。Apps Scriptのタイムゾーンが `Asia/Tokyo` であることを確認します。

上記のスプレッドシートから開いた**紐づけ型**GASなら、`setup()` がシートIDを取得してスクリプトプロパティ `SPREADSHEET_ID` に保存します。単独型GASを使う場合だけ、先に **プロジェクトの設定 → スクリプト プロパティ** で `SPREADSHEET_ID` を `1s-N6dr2nZNV5O7RlI66umnhqjtWX8WGN4fh9UAsU0Yw` に設定してください。IDをソースへ直書きしません。

## 3. シートを作る

1. Apps Scriptの関数一覧から `setup` を選び、**実行**します。
2. 初回のGoogle権限画面は内容を確認し、対象のGoogleアカウントで承認します。組織の管理者設定で拒否された場合は回避せず、その設定のままでは利用できないことを確認してください。
3. シートに **抽選設定**、**コード管理**、**ガチャ履歴** ができ、[SHEETS.md](../SHEETS.md) の見出しと一致することを確認します。元の空タブが残っていても問題ありません。
4. **プロジェクトの設定 → スクリプト プロパティ** に `SPREADSHEET_ID` が保存されていることを確認します。

`setup()` は不足するシートと見出しだけを作ります。既存の履歴・設定値を消しません。既存の見出しが異なる場合は停止します。

## 4. 運営値を入力する

**抽選設定**の2行目へ現行サイト用の設定を入力します。入力前に E〜H列を **表示形式 → 数字 → 書式なしテキスト** にしてください。時刻と日付は表示された文字列を厳密に読み取ります。列の意味は [SHEETS.md](../SHEETS.md) を参照してください。

| 列 | 入力 |
|---|---|
| A キャンペーンID | `night-gacha` |
| B キャンペーン名 | 運営側で入力 |
| C 有効 | すべて確認するまでは `OFF`、公開開始時に `ON` |
| D 開催曜日 | 現行サイトは水曜日なので `3`（月曜=1） |
| E 開始時刻 / F 終了時刻 | 運営側で `HH:mm` 形式で決定・入力。終了を当日末尾にする場合は `24:00` |
| G 開始日 / H 終了日 | 期間を限定する場合だけ `YYYY-MM-DD`、継続開催なら空欄 |
| I 当選確率 | 運営側で決定した0〜1の小数。パーセント表示ではなく小数で入力し、例の値を本番へ流用しない |
| J 当選ポイント | 現行サイトの表示・通信は100pt専用。100pt企画として承認された場合に `100` を入力 |
| K 当選上限 | 1開催日あたりの当選数を運営側で決定・入力 |
| L 許可オリジン | `https://clear-official.github.io`（リポジトリ名と末尾 `/` は付けない） |
| M 備考 | 任意 |

**コード管理**には、開催日ごとに1行追加します。Aは `night-gacha`、Bはその開催日の水曜日を `YYYY-MM-DD`、Cは正式な共通キャンペーンコード、Dは `ON` です。B〜C列は入力前に**書式なしテキスト**にしてください。コードは英数字・`_`・`-` の3〜64文字で、先頭は英数字です。同じコードを別の開催日やキャンペーンで再使用しないでください。

正式な**当選確率、開催時刻、当選上限、キャンペーンコード、公開日**は今回決めていません。入力が不足した状態、コード未登録、重複・不正な設定では抽選を開始しません。

## 5. Webアプリとしてデプロイする

1. Apps Scriptで **デプロイ → 新しいデプロイ → ウェブアプリ** を選びます。
2. **次のユーザーとして実行：自分**、**アクセスできるユーザー：全員**を選び、デプロイします。これによりGASは公開され、シート操作はデプロイしたアカウントの権限で実行されます。Workspaceの管理設定で全員公開が禁止されている場合は停止し、別の認証方式を設計してください。
3. 権限画面を確認して承認し、`https://script.google.com/macros/s/.../exec` 形式のURLを控えます。Webアプリを更新したら、**デプロイを管理**で新しいバージョンへ更新します。保存だけでは既存の `/exec` に反映されません。
4. GitHub Pagesの `app.js` 冒頭の `GAS_WEB_APP_URL` をその `/exec` URLへ変更します。現時点の公開版はプレースホルダーのままです。この作業では変更・commit・pushしていません。
5. サイトを開き、開催条件に合うときに「ガチャを回す」が押せることと、抽選後に **ガチャ履歴** に記録が1件作られることを確認します。

## 6. 安全なテスト手順

本番の抽選履歴・コードをテストに使わず、スプレッドシートを**コピー**し、別の紐づけ型GASプロジェクトへ同じコードを貼り付けてテストします。コピー側で `setup()` を実行し、`SPREADSHEET_ID` がコピーのIDであることを確認します。テスト用コードは実際に使えない文字列にします。

1. コピー側の抽選設定で、試験当日の曜日・開催時間、当選確率 `1`、ポイント `100`、上限 `1`、有効 `ON` を設定します。現行サイト用 `night-gacha` は水曜専用なので、他の曜日の試験には別ID（例：`test-gacha`）を使います。
2. コピー側のコード管理に、同じキャンペーンID・試験日・無効なテストコードを1行登録します。
3. コピー側のApps Scriptエディターで一時的に `ManualCheck.gs` を追加し、次を貼って `manualCheck` を実行します。実行ログとコピー側の履歴を確認します。このファイルは**本番プロジェクトへコピーしない**でください。

   ```js
   function manualCheck() {
     Logger.log(drawApi('12345678-1234-4234-8234-123456789abc', 'test-request-1', 'test-gacha'));
   }
   ```
4. 同じユーザーID・別リクエストIDでもう一度呼び、結果が `already_played` で、`SUCCESS` 行が1件だけであることを確認します。同じリクエストIDの再送ではログ行も増えません。
5. 抽選設定の時間を現在時刻の外へ変えて `closed`、有効を `OFF` にして `closed`、コード行を外して `temporarily_unavailable` を確認します。不正なUUIDと存在しないキャンペーンIDは `temporarily_unavailable` です。
6. 別のUUIDで上限を超える抽選を行い、当選確率が1でも0ptになることを確認します。確率を0にして非当選も確認できます。
7. テスト後、本番シートの値が変わっていないことを確認します。

このリポジトリのローカル模擬テストでは正常抽選、重複、曜日・時刻、無効設定、コード不足、上限、ID検証を確認しています。実際のGoogle Sheets・GAS・サイト間通信は未検証です。

## 7. 確認するセルと障害時の見方

- 正常抽選：**ガチャ履歴**の次の行で、Aに実行日時、Bに開催日、Cに端末ID、DにキャンペーンID、Eに `win` / `lose`、Fにポイント、Hに `SUCCESS`、KにリクエストID、Lに重複判定キーが入ります。Gのコードは当選時だけ入ります。
- 別リクエストでの再参加：同じB・C・Dの `SUCCESS` は増えず、Hが `DUPLICATE` の行が追加されます。
- 開催時間外：Hが `REJECTED`、Iが `OUTSIDE_SCHEDULE` です。
- コード設定不備：Hが `ERROR`、Iが `CODE_CONFIGURATION` です。詳しい原因は Apps Script の **実行数** と実行ログで確認します。
- シート名・見出し・設定行が不正でログへ書けない場合、サイトには一般的な一時利用不可を返し、内部原因は Apps Script の実行ログに記録します。

運営集計は履歴の H列 `SUCCESS` / `DUPLICATE` / `REJECTED` / `ERROR` と E列 `win` / `lose` を集計できます。今回はAnalyticsを追加していません。

## 8. セキュリティと運用上の制約

- 現在のユーザーIDはブラウザーの `localStorage` にある端末IDです。別端末・ストレージ削除では別IDになるため、同じ**人**の再参加を完全には防げません。Clear側の安定した認証済みIDを利用できるようになったら、サイト・GAS双方を変更してください。
- iframeの送信元チェックは通常のサイト通信を制限しますが、公開GASを直接呼ぶ利用者の本人確認にはなりません。景品やポイントを本番付与する前に、この制約を運営側で評価してください。
- 共通キャンペーンコードは当選者へ返す必要があり、共有・転送もできます。コード単体でポイントを引き換えられる運用なら、引換側でも本人・当選履歴を確認してください。確率・上限・コードをフロントコードへ埋め込まず、シートの編集権限を絞ってください。
- `SPREADSHEET_ID` はスクリプトプロパティ、コードはシートで管理します。パスワード・OAuthトークンはGitHubへ登録しません。
- 抽選と履歴保存は `LockService.getScriptLock()` で直列化します。大量アクセス時にはApps Scriptの実行時間・シートの読込量に制限があります。
